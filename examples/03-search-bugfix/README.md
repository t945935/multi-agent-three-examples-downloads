# 實例三：網站搜尋錯誤修復

## 目標與分工

修復搜尋框輸入空白時頁面出錯的問題，練習修復與獨立審查。

本實例是工作流程提示詞，尚未附帶故障網站。執行前須選定可修改的網站專案，提供啟動方式與重現步驟，並確認空白輸入的預期行為。

## 提示詞

可直接開啟 [prompt.txt](prompt.txt) 複製完整指令。

```text
請用修復與獨立審查兩個子 Agent，處理搜尋框輸入空白時出錯的問題。

主 Agent：
- 先閱讀目標專案規範，確認啟動方式、重現步驟及預期行為。
- 缺少專案或重現資料時先回報缺口，不虛構已修復成果。
- 將修改限制在搜尋相關範圍，負責整合與最後驗收。

修復 Agent：
- 先重現問題，建立能捕捉原始錯誤的回歸測試，再做最小修改。
- 執行相關測試，回報修改檔案、原因、命令與結果。

審查 Agent：
- 修復完成後只讀檢查差異與相關程式。
- 檢查空字串、只有空白、正常關鍵字及查無結果等情境。
- 每個問題附檔案位置、觸發條件與影響。
- 區分必須修復的問題與可選建議。

有必要問題時交回修復 Agent，修改後重新驗證。
完成條件：原始錯誤已修復、正常搜尋仍可使用、相關測試通過，
且必要審查問題均已處理。無法執行的檢查須明確回報。
```

## 驗收清單

- [ ] 原始問題有可重現步驟，空白輸入的預期行為已確認。
- [ ] 回歸測試能在修復前暴露問題，在修復後通過。
- [ ] 正常搜尋及查無結果仍符合預期。
- [ ] 必要審查問題已修正並重新驗證。
- [ ] 最終報告附修改摘要、驗證證據與剩餘限制。
